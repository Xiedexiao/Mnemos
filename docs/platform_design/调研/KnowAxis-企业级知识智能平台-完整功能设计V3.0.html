本文是一份完整的产品功能设计，用于产品评审、研发拆解、实施配置和验收对照。它描述平台“应该具备什么功能、按什么规则运行、边界在哪里”， 不展开技术选型与接口字段级细节；接口契约以研发设计文档为准。

文档定位

全公司级知识智能平台的产品功能总设计，覆盖基础能力、AI 能力与治理机制三部分。

适用范围

总部与分支机构、业务部门与职能部门、内部员工与受控外部协作者，以及通过 API/MCP 接入的业务系统与 AI Agent。

版本说明

V3.0 整合 V2.1 产品功能设计与 V6 后端能力设计，并把权限、审核、更新三条治理主线写入正式功能章节。

设计原则

六条原则贯穿全部功能

  1. 基础功能 100 分：企业知识库该有的能力一个不少——上传、组织、协作、权限、搜索、运营，全部做扎实。
  2. 智能能力做增量：用 AI 本体、知识图谱、自动沉淀带来体验跃升，而不是用 AI 替代基础功能。
  3. 权限先行：权限过滤发生在检索、召回、模型调用之前；没有权限的内容不进入候选，更不进入 Prompt。
  4. 证据可追溯：每条可发布知识、每条高风险结论都能回到原文、业务记录或审批凭证。
  5. 变更可闭环：知识更新以“变更单”为载体，从原因、影响、审批、生效、通知到验证形成闭环。
  6. 治理可运营：权限、质量、审核都有指标、有责任人、有周期动作，而不是一次性配置。

01 · Overview

1 · 产品全景

平台采用自底向上的五层架构：底座提供身份、权限、安全、版本证据与模型网关；中间层负责知识进来、被理解、被组织； 上层负责被找到、被使用、被运营。每一层都为上一层提供确定的能力，而不是把所有逻辑堆在一个“AI 问答”入口里。

1.1 平台定位

对企业

把散落在文件、系统、聊天记录和老员工脑子里的知识，变成可检索、可问答、可追溯、可更新、可审计的组织资产。

对个人

少问人、少踩坑、少翻文档；一线员工能在一分钟内拿到“当前有效、适用于我这个场景、有依据”的答案。

1.6 平台边界

五条不做的边界

  • 不替代业务系统主数据：设备、物料、客户、工单等权威数据仍由 PLM/ERP/MES/QMS/CRM 负责，平台做关联与语义化，不做交易主库。
  • AI 不宣布事实：AI 负责发现、抽取、归一和建议；高风险知识必须由责任人确认或权威角色发布。
  • 不把“全公司可见”当作默认：默认最小可见；派生知识的可见范围不得宽于源证据。
  • 不让内容绕过治理：发布、权限、导出、删除、合并都必须经过对应审批，紧急通道也必须补审。
  • 不把 Prompt 当规则引擎：可测试的规则进入规则库/策略引擎，Prompt 只负责表达与生成。
02 · Identity & Permission

2 · 角色、组织与权限

权限中心是平台的安全底座。它要回答四个问题：谁（身份）、对什么（资源）、能做什么（动作）、 在什么条件下（密级、时间、来源、目的）。四条答案合在一起，才构成一次可执行的授权判断。

角色体系

平台预置 10 类角色，支持按空间/目录/知识域组合授权。角色是“职责包”，不是“超级权限”；任何角色都不能默认突破密级与权限上限。

角色职责关键权限与边界
平台管理员租户、空间、连接器、模型、系统配置系统配置权；不默认拥有业务内容阅读权；高风险操作双人复核
空间管理员空间成员、目录、权限、审核流程管理空间内容与成员；可查看受限文档清单，但正文仍受密级约束
知识 Owner知识质量、复审、发布决策管理本领域知识；可发布 L2；L3 需评审委员会或指定权威角色
审核员内容审批、抽检、合规检查review 权限；不默认拥有编辑权，避免“边审边改”失去四眼
作者 / 贡献者创建、编辑、提交审核编辑自己或协作知识；不能自审；不能自行提权
读者查看、搜索、问答、评论、反馈只读 + 互动；下载/分享按密级与空间策略
审计员审计查询、合规导出、异常核查只读审计数据与权限快照；不能修改内容或权限
安全 / 合规密级、外链、DLP、合规审批跨域合规审批与阻断权；使用需留痕
外部协作者供应商、客户、外包等受控协作独立访客身份、NDA、到期自动失效、范围受限
服务账号 / AgentAPI、MCP、RPA、数字员工最小 scope、短时令牌、委托身份、独立审计

2.1 权限模型：四层组合

平台不采用单一模型，而是四层组合：RBAC 负责“岗位能做什么”，ABAC 负责“在什么条件下能做”，关系授权负责“因为参与了这个项目/客户所以能看”，ACL 负责“这一篇文档单独授权”。

L4 执行层
检索前生成过滤条件 → 召回后逐 Chunk 复核 → 答案输出前 DLP 校验 → 审计留痕
L3 策略层
RBAC 角色 + ABAC 条件（密级/时间/部门/来源/目的）+ 关系授权（项目/客户/供应商）+ 资源 ACL
L2 资源层
租户 → 空间 → 目录 → 文档 → Chunk；图谱实体、关系、官方答案、规则、附件同级受控
L1 身份层
SSO 用户、组织树、用户组、自定义人员集合、访客、API Key、服务账号、Agent 身份

五条判定规则

  1. 默认拒绝：没有显式允许，就是不可见；新空间、新文档默认仅创建者与空间管理员可见。
  2. Deny 优先：任何一条 deny 命中即拒绝，Allow 不能覆盖 Deny。
  3. 上限约束：子级授权不得超过父级；密级不得超过父级；任何提权必须审批。
  4. 动作分离：能看 ≠ 能问 ≠ 能引用 ≠ 能下载 ≠ 能分享；每个动作独立判定。
  5. 权限先行：过滤发生在召回之前；模型永远看不到未授权内容。

2.2 权限动作：13 种，不合并

企业知识库最常见的权限事故，是把“可见”当成“可用”。平台把动作拆细，确保“能读到”和“能进入 AI 回答”“能下载”“能转发”是四件事。

动作含义典型规则
view查看文档详情与正文最基础权限；有 view 不等于可搜索
search出现在搜索结果中可被搜到但不一定能打开；用于“只暴露标题”的场景
ask可作为 RAG 证据进入回答与 view 分离；涉密内容可 view 但不能 ask
cite可作为引用展示给用户必须同时满足 view 或 ask；无权限端点只提示“存在未授权依据”
download下载原文件或附件按密级与空间策略；下载即水印、留痕
share创建分享链接或邀请访客链接权限 ≤ 源文档权限；外部分享需审批
manage编辑内容、移动、归档不自动包含 authorize；移动可能触发权限重算
authorize配置权限、授权他人不能自授；超过阈值需审批；受权限上限约束
publish_official发布官方答案、规则、L3 权威知识指定角色或委员会；必须绑定证据与审批凭证

2.3 权限继承与上限

继承让权限可维护，上限让继承不出错。两者必须同时存在：只有继承，权限会越配越宽；只有上限，没有继承，管理成本会失控。

继承规则

  • 资源层级：租户 → 空间 → 目录 → 文档 → Chunk。
  • 子级默认继承父级；目录可覆盖空间，文档可覆盖目录。
  • Chunk 默认继承文档；Chunk 级例外只对合规/法务场景开放。
  • 恢复继承会删除子级策略：必须先导出权限快照并二次确认。

上限规则

  • 主体上限：子级授权的主体集合 ⊆ 父级允许的主体集合。
  • 密级上限：子级密级不得低于父级要求；高密级内容进入低密级空间需审批。
  • 动作上限：子级不能授予父级未开放的动作（如父级禁止下载，子级不能开放）。
  • 例外：法务/安全 break-glass 可临时突破，但必须带理由、时限、事后审计。
场景默认策略说明
文档移动到其他目录重置为继承 + 差异预览移动前展示“谁将获得/失去访问”，确认后才执行
文档复制到其他空间不继承源权限，按目标空间重算跨空间复制不得把源空间的授权带过去
目录单独授权允许，但受父级上限约束超过上限需空间管理员审批
恢复继承二次确认 + 快照恢复后子级唯一权限被清除，需可回滚
唯一权限过多配额告警 + 治理任务按空间统计“破坏继承”比例，超过阈值进入治理清单

2.4 密级与派生权限

密级回答“这类内容最多能让谁知道”，ACL 回答“具体让谁知道”。最终可见范围取两者交集。派生知识（摘要、案例、FAQ、图谱事实、官方答案）的可见范围，取全部源证据中最严格的那一条。

密级定义与示例默认可见外发 / 导出
公开可对外发布的宣传、公开标准、招聘信息所有人（含外部）允许；保留来源标识
内部制度、SOP、普通培训材料、项目文档全体员工外发需审批；导出加水印
秘密客户合同、报价、未发布产品、工艺参数授权部门/项目组默认禁止；特批 + 水印 + 审计
机密核心配方、源代码、并购信息、重大风险指定人员集合禁止导出；仅受控终端查看

密级运行规则

  • 定密：AI 根据内容、来源、模板给出建议密级；上传人确认；无确认时按空间默认密级处理。
  • 降密：必须审批并留痕；降密后重新计算派生知识与分享链接的可见范围。
  • 升密：即时生效，通知已授权用户；已下载/已导出内容进入追踪清单。
  • 标识：页面页眉、预览水印、导出文件头显示密级、责任人、导出时间。
  • 字段级：表格支持列级脱敏（价格、客户、身份证号）；敏感字段不进入向量化与外部模型。
  • 派生交集：任何 AI 摘要、案例、FAQ、图谱事实、官方答案发布前，计算源证据权限交集；交集为空则不可发布。

2.5 分享与外部分享

分享链接是外泄的头号入口，平台把它作为一等治理对象：有类型、有审批、有期限、有身份、有日志、可盘点、可一键撤销。

链接类型适用场景控制规则
仅组织内跨部门协作、临时项目必须登录企业身份；权限 ≤ 源文档；可设有效期
指定人定向发给某位同事或外部顾问逐人授权；外部人需访客身份 + NDA；默认 30 天到期
任何人可访问公开资料、招聘、对外宣传默认关闭；仅“公开”密级可用；必须审批 + 域名白名单 + 水印

链接级控制

  • 权限：只读 / 可评论；默认不含下载与转存。
  • 有效期：7 / 30 / 90 天或自定义；到期自动失效。
  • 密码或验证码：对外部访问强制。
  • 访问者水印：姓名/邮箱 + 访问时间 + 链接 ID。
  • 访问日志：谁、何时、从哪、看了多久；异常告警。
  • 一键撤销：撤销后所有缓存与预览地址立即失效。

外部协作者

  • 独立访客身份，不与员工账号混用。
  • NDA 勾选与到期时间；到期自动禁用。
  • 可见范围限定在指定空间/目录，不继承“内部”默认权限。
  • 禁止转存、打印、复制（按密级）；仅在线预览。
  • 季度盘点：长期未访问的访客自动进入复核清单。

分享链接的“权限上限”

链接权限永远不能高于源文档权限。一个只能查看的文档，不能通过链接变成可下载；一个“秘密”级文档，不能生成“任何人可访问”链接。发布链接时系统自动校验，不通过则要求先调整源权限或走特批。

2.6 撤权传播：撤权不是“改一条记录”

权限撤销后，平台必须在所有派生通道里同步失效，并能证明失效已发生。任何一个通道漏掉，撤权就只是“界面上看起来没了”。

通道失效方式目标时延验证方式
搜索索引权限字段刷新 + 查询时实时判定≤ 5 分钟被撤权用户搜索无结果
向量索引命名空间/分片标记 + 逐条复核≤ 5 分钟问答不召回
图数据库权限投影刷新；路径端点过滤≤ 5 分钟图谱路径不展示
答案缓存权限版本变更使缓存键失效≤ 1 分钟缓存不返回旧答案

离线文件DRM/加密容器到期；下次联网校验≤ 24 小时离线打开失败

三条硬规则

  • Fail-closed：源权限服务不可用时拒绝访问，不回退到旧权限快照。
  • 权限版本：每次授权变更生成新版本；缓存、答案、Evidence Pack 都记录版本，重放时用当前权限复核。
  • 撤权演练：每季度做一次负向测试，验证被撤权用户在搜索、问答、图谱、导出、通知等入口都看不到内容。

2.7 AI 与 Agent 权限

AI 链路会复制、缓存、重组知识，因此需要比文档权限更细的控制。平台遵循一条总原则：模型看到的，永远不超过提问者此刻有权看到的。

控制点设计规则
检索前过滤先生成权限过滤条件，再做关键词/向量/图谱召回；未授权内容不进入候选集。
逐 Chunk 复核召回后按当前权限再校验一次，防止索引滞后；失败即丢弃，不做“降级展示”。
会话隔离会话绑定用户与委托身份；共享会话按接收者权限逐条重放；禁止把 A 的会话记忆用于 B。
长期记忆按用户/租户分区；记忆写入前做权限与密级校验；敏感记忆不跨会话复用。
答案缓存缓存键包含权限版本、密级、知识版本；高密级不缓存或仅按用户缓存。
索引隔离不同密级独立索引/命名空间；embedding 与原文同等保护；不进入训练集。
引用脱敏无权限端点不展示标题、编号、摘要；只提示“存在未授权依据”。
注入防护入库检测隐藏指令；检索结果做指令/数据分离；输出做 DLP 与泄露校验。
Agent 委托链Agent 身份 ∩ 委托用户权限；按 tool 级 scope；子 Agent 不继承父权限；长任务重新鉴权。
MCP / API默认只读；写操作回原业务系统审批；配额、超时、人工中断、调用审计。

2.8 审计与取证

审计不是“记日志”，而是“在需要时能还原一次访问或一次决策”。平台把审计分为操作审计、内容审计、AI 审计三类，统一进入不可篡改的审计流。

审计类型记录内容典型用途
操作审计登录、搜索、查看、下载、分享、导出、权限变更、删除谁在何时访问了什么；异常行为检测
内容审计发布、更新、审批、驳回、下架、合并、归档内容变更追溯；ISO 9001 文档控制证据
AI 审计提问、检索候选、引用、模型版本、Prompt 版本、拒绝原因、Evidence Pack回答可复现；幻觉与越权排查
Agent 审计Agent 身份、委托用户、工具调用、参数、返回范围、是否人工中断Agent 行为追溯；权限边界验证

审计能力

  • 哈希链/WORM 存储，日志只追加不修改。
  • 审计日志单独授权：审计员可查，普通管理员只能看自己的操作。
  • 分级留存：等保 ≥ 6 个月；财务/质量/安全按法定年限；legal hold 可延长。
  • 异常检测：批量下载、非工作时间、短时高频、跨空间遍历、异常导出。
  • 一键导出等保、ISO 27001、ISO 9001 审计包。

权限治理运营

  • 季度权限复核：按空间/文档/用户三视角，Owner 对账，非响应升级。
  • 职责分离：作者 ≠ 审核人；授权人 ≠ 被授权人；管理员日常不参与业务审批。
  • 孤儿权限：离职、调岗、项目结束后自动识别并清理。
  • Break-glass：带理由、时限、事后审计；使用即告警。
  • 冻结期：财报、审计、重大发布期间限制权限变更。

3 · 知识入库

企业 90% 的知识已经存在——Word、PDF、Excel、制度、SOP、会议纪要、工单记录。平台的核心不是让人重新写一遍， 而是把这些内容快速、准确、可追溯地变成结构化知识，同时允许人工补充零散经验。

3.1 文件上传与批量导入

能力规则
全格式支持Word、PDF、Excel、PPT、Markdown、TXT、图片（JPG/PNG/CAD）、音视频、压缩包；不支持格式给出明确提示，不静默失败。
批量上传文件夹拖拽、多选、压缩包；自动识别目录结构并映射为空间目录；支持“先预览再入库”。
大文件单文件最大 2GB；断点续传；超大文件转异步任务，可在任务中心查看进度。
去重检测上传时按内容 hash + 标题 + 元数据检测相同/相似文件；提示“新建版本 / 作为新知识 / 取消”。
失败处理格式不支持、加密、损坏、超限分别给出原因；失败文件进入“待处理”，不占用知识条目。

3.2 人工录入与批量导入

适合零散经验、FAQ、没有现成文件的知识点。人工录入与 AI 解析同等待遇：同样进入图谱、走审核、支持版本、评论、关联与权限。

自定义字段

  • 字段类型：单行文本、多行文本、数字、日期、下拉、单选、多选、附件、关联知识/实体。
  • 字段必填/可选、默认值、校验规则、可见性。
  • 召回字段：可选择 1 个或多个字段作为优先检索字段，提高精准度。
  • 字段变更影响存量知识时，提示并生成迁移任务。

模板与批量

  • 模板中心：故障案例、FAQ、SOP、异常处理、会议纪要、项目复盘等。
  • 选择模板后自动显示字段与填写引导，避免漏项。
  • Excel 批量导入：按模板填写，校验后一键导入；错误行可下载修正。
  • 批量导入进入“待审核”，不直接发布。

3.3 业务系统自动同步

平台不替代业务系统，而是通过连接器把业务对象与过程记录同步进来，形成可检索、可关联、可沉淀的知识来源。

数据源同步内容同步方式关键规则
ERP / MES工单、生产记录、停线事件、参数调整增量 + 事件保留业务键与状态；变更触发知识更新
PLM / PDM图纸、BOM、ECR/ECO、版本替代版本比对 + 事件版本关系必须同步；旧版标记 replaced
QMSNCR/CAPA、异常、检验记录、供应商质量事件 + 定时异常关闭触发沉淀；根因保持 suspected/confirmed
OA / HR制度、通知、组织架构、岗位定时 + 增量组织变更触发权限重算与知识复审
CRM / 客服客诉、服务记录、解决方案事件 + 定时客户权限继承；敏感字段脱敏
项目系统项目、里程碑、验收、风险事件 + 定时项目关闭生成项目知识包

首次全量

范围预览（数量、样本、权限、密级、敏感风险）→ 确认 → 全量拉取 → 质量抽检。

增量同步

updated_at 游标、checksum、版本号、Webhook 四选一；事件带业务版本号，拒绝旧事件覆盖新版本。

失败与对账

鉴权失败暂停并通知；权限同步失败不得进入可检索状态；每日对账，差异进入任务池。

3.4 飞书 / 企微 / 网盘文档同步

在线文档支持“关联”而非“复制”：源文档更新自动同步到知识库，避免重复上传下载。同步必须明确权威源，否则会出现双向覆盖。

同步规则

  • 权威源：默认在线文档为权威源，知识库为只读镜像；如需在知识库编辑，必须切换为“知识库权威”并停止反向同步。
  • 冲突策略：双向同步时，检测到双方都修改则加编辑锁并提示人工合并；禁止静默覆盖。
  • 权限继承：在线文档的协作者权限同步为知识库 ACL；外部协作者按访客规则处理。
  • 删除同步：源文档删除 → 知识库进入“待确认下架”，不直接物理删除。
  • 版本留痕：每次同步生成版本，记录源版本号与同步时间。

3.6 人工校对与入库

入库预览

先预览解析效果：标题、目录、表格、图片、元数据；确认后再入库，避免“先入库再返工”。

轻量编辑

调整格式、补充元数据、写备注、划词评论；不用于从零写长文档，长文档仍以源文件为准。

实体关联

校对时可增删实体、修正关系、补充关联知识；低置信度实体高亮提示。

权限设置

入库时设置可见范围、密级、可编辑/可管理角色；默认继承空间，修改需符合权限上限。

选择模板

SOP、制度、会议纪要、异常报告等模板让 AI 按结构提取，提升字段准确率。

提交审核

校对完成一键提交；系统生成审核基线（内容 hash + 证据快照），进入审批流。

06 · Review & Publish

6 · 审核与发布

审核的目标不是“多一道手续”，而是用可接受的成本把错误挡在发布之前，并在事后证明“谁在什么时候、基于哪一版、批准了什么”。 平台把审核设计成可配置、可分级、可度量、可取证的治理服务，而不是一个“通过/驳回”按钮。

6.1 审核原则与流程

六条审核原则

  1. 审变更，不审全文：默认只审差异段落、影响条款与新证据，降低审批负担。
  2. 审基线，不审“最新”：提交时冻结内容版本，审批人看到的是一个确定快照。
  3. 四眼原则：作者不能自审；双审必须来自不同角色或部门。
  4. 风险分级：风险越高，审批强度越高；低风险批量处理，避免审核堵车。
  5. 证据化：每条审批生成凭证，绑定内容 hash、证据快照、身份与时间。
  6. 审核不等于质量：发布后仍要抽检、反馈、复盘；审核只是第一道门。

07 · Update & Lifecycle

7 · 更新与生命周期

知识库最难的不是把资料放进去，而是判断资料还是否有效、一次变更有没有改全、错误知识能不能立刻下线。 平台用变更单 + 生命周期状态机 + 复审 + 影响闭环回答这三个问题。

7.1 生命周期状态机

每条知识在任何时刻都处于一个明确状态，状态决定它在搜索、问答、图谱和通知中的行为。

状态含义进入条件检索 / 问答行为
草稿未提交审核创建或编辑仅作者可见；不检索
待审核已提交，审批中提交审核作者/审核人可见；不进入公共检索
待生效已批准，未到生效日审批通过 + 未来生效日可按权限查看；问答明确“尚未生效”
有效当前可用发布或生效日到达正常检索与问答；按权威等级排序
待复审到达复审周期复审到期可检索；回答提示“待复审”或降权
疑似过期出现过期信号源变更/反馈/冲突/长期未用不作为权威答案；可提示后回答
已过期确认失效复审失败/超过有效期默认不回答；历史查询可见
被替代有新版本替代新版本发布并建立 replaces指向新版本；旧版本不进入当前答案
冲突与其他权威知识矛盾冲突检测或人工标记展示冲突双方，不强行下结论
已下架主动撤回下架审批通过立即排除；历史与审计可见
归档不再使用但需留存过期/替代/项目关闭默认不检索；归档库可按需查询

状态转换的硬规则

“有效 → 已过期”不能由系统静默完成，必须有原因（到期、复审失败、源系统作废、人工确认）；“已发布 → 已下架”必须留痕并通知已读用户；“归档”不等于“删除”，删除必须检查引用、留存策略与 legal hold。

7.4 版本与生效期

版本规则

  • 版本号：主版本.次版本.修订号；与源系统版本建立映射。
  • 文字修订 → 修订号；内容/步骤调整 → 次版本；参数/结构/替代 → 主版本。
  • 版本变更级别决定审核强度与通知范围。
  • 历史版本永久可查（按留存策略），但默认不参与当前问答。

生效期规则

  • 三个时间：预告日（announce）、生效日（effective）、失效日（expires）。
  • 支持未来生效与到期自动失效，不依赖人工切换。
  • 过渡期新旧版本并存，标注适用范围（地区/产品线/客户/批次）。
  • as-of 查询：可查看“某一历史时点有效的版本”。
  • 回答必须输出“依据版本 + 生效日期”。

7.5 审核基线

基线规则

  • 冻结：提交审核时冻结内容 hash、解析结果、证据快照、适用范围。
  • 差异再审：审核期间源内容变更 → 标记“基线已变”，生成差异，审批人选择继续/重审/撤回。
  • 只审 diff：默认展示变更段落、影响条款与新证据；支持全文模式。
  • 发布校验：发布前比对当前内容 hash 与审核基线；不一致则阻断并要求重新确认。
  • 凭证绑定：审批凭证记录基线 ID，保证“批的就是这一版”。

7.6 影响分析与闭环

影响分析不能停在“提醒”，要变成可执行、可豁免、可验证的任务。平台沿图谱关系、引用关系、培训关系与外部文档关系计算影响包。

影响对象示例处理方式
知识引用了被变更制度的 SOP、FAQ、案例生成修订任务；高风险阻断发布
官方答案 / 规则基于旧版参数的标准答案下线或重算；重新审批
培训 / 考试培训材料、考试题库、上岗资格生成培训更新任务；通知 HR/培训
外部文档客户手册、供应商文件、投标材料生成对外更新任务；审核后发布
现场物料打印件、工位看板、检查表生成替换任务；记录完成时间
系统配置规则引擎、报表口径、接口字段生成系统变更任务；与 IT 联动

任务化

影响项批量生成任务，带模板、SLA、责任人；支持“确认无需修改”并记录理由。

阻断

高风险影响项未完成或未豁免时，变更单不能关闭，新版本不能发布。

看板

影响任务完成度、逾期率、豁免率；按领域/部门汇总。

7.7 复审机制

复审不是“每年重新看一遍”。平台按知识类型、变化频率、访问量、风险级别动态安排复审，并提供轻量动作降低负担。

知识类型复审周期过期行为主要触发
法规 / 合规变更触发 + 年度立即下线，问答拒答法规、标准、监管口径变化
制度 / 流程6 个月降权 + 显著提示制度修订、组织调整
SOP / 工艺6 个月高风险类隐藏工艺、设备、图纸变更
产品 / 价格季度隐藏产品发布、调价
故障案例12 个月标注“历史案例”新案例、复发、根因修正
项目经验12 个月归档项目关闭、验收
基础知识24 个月标注，不隐藏无
官方答案3 个月下线并回退普通问答证据、规则、版本变化

四个复审动作

  • 确认有效：延长有效期，更新“最后验证于”徽章。
  • 需修改：进入变更单，按更新流程处理。
  • 建议归档：不再使用但需留存。
  • 转交：Owner 变更或临时委托。

降低复审疲劳

  • 低风险批量确认；高风险逐条确认。
  • 展示“最后验证于 + 验证人”，让用户参与监督。
  • 按访问量/风险动态调整周期，不搞一刀切。
  • Owner 空缺 → 上级 → 领域组 → 知识管理员兜底。
  • 用户“已过时”反馈达到最小样本后自动触发复审。

8.4 本体治理

Schema 变更

  • AI 或用户提出 SchemaProposal：新类型、属性、关系、约束。
  • 本体管理员审核；兼容性检查；样本迁移预演。
  • 影响分析：哪些知识、索引、问答、评测会受影响。
  • 发布新 Schema 版本；图谱重投影；可回滚。

治理分级

  • L0 不抽取：只做全文检索，适合临时/低价值内容。
  • L1 弱绑定：自动抽取，用于搜索增强。
  • L2 待确认：用于提示和候选，不作为权威依据。
  • L3 已确认：可用于排序、RAG 约束、推荐。
  • L4 权威控制：图纸、制度、报价、财务、工艺、官方答案，需责任人、版本、复审、评测。

强治理触发条件

  • 涉及价格、报价、合同金额、质量标准、工艺参数、图纸版本替代、财务审计、合规、HR 政策。
  • 置信度低于阈值；与已有官方知识冲突；影响大量文档或高频问题。
  • 触发后：必须人工审核；不得由 AI 直接升级为正式事实；不得扩大权限范围。

10.4 发布等级与风险门禁

等级名称说明可见范围与用途

L2已确认知识责任人审核通过的经验按权限可见；可参与普通问答
L3权威知识专家评审/正式发布的标准按权限可见；可用于高风险结论；搜索置顶

高风险门禁

  • 派生知识权限 ≤ 源证据权限交集；案例不得比原始工单更可见。

11.2 影响分析

影响分析是变更单的核心输入。平台沿“依赖、适用、替代、依据、前置、责任”等关系做广度优先遍历，并按影响程度分级。

影响分级

高风险（必须改）、中风险（建议改）、低风险（知会）；每级有不同 SLA。

影响包

受影响知识、部门、岗位、培训、考试、外部文档、打印件、供应商文件。

闭环

任务分派、豁免记录、完成验证、看板；未完成阻断高风险发布。

11.3 权限与图计算

图查询的权限规则

  • 端点过滤：路径中任一节点无权限，整段路径不展示；不泄露节点名称与关系类型。
  • 计数保护：不返回“还有 N 个无权限节点”这类信息；必要时聚合为“存在未授权关联”。
  • 推荐过滤：专家推荐只在有权限的知识范围内聚合；设置最小案例数，避免反推敏感项目。
  • 影响分析：只展示有权限的影响项；无权限部分由管理员在受控视图查看。
  • 缓存：图查询结果缓存包含权限版本；权限变更即失效。

12.2 高级筛选与排序

筛选维度

  • 空间、知识类型、标签、分类、作者、时间范围。

  • 密级、来源系统、适用产品/设备/项目。
  • 组合筛选；筛选条件可保存为“我的视图”。

排序策略

  • 综合：相关度 + 热度 + 权威性 + 新鲜度。
  • 时间：最新发布/更新优先。
  • 热度：浏览、点赞、收藏、引用。
  • 权威：L3 权威知识优先；待审核/过期降权。
  • 管理员可置顶重要知识，但置顶不突破权限。

12.6 搜索的权限与泄露控制

四条规则

  • 建议不泄露：联想词只从可见集合生成；高密级标题不进入热门词库。
  • 计数不泄露：只统计授权结果；禁止“N 条无权限”的提示。
  • 预览不泄露：结果摘要只展示有权限的片段；无权限附件不生成预览。
  • 排序不泄露：热门榜、最新动态、相关推荐都按查看者权限重算。

12.7 精准知识索引

精准索引的目标是“定位到粒度”，而不是只返回一个文档链接。平台为每条知识建立三类索引，并在检索时组合使用。

索引内容用途

定位信息

每条结果带文档、页码、段落、表格区域、步骤号；点击直达。

索引更新

内容变更增量更新；权限字段与新鲜度字段同步刷新；索引可重建。

13 · 可信智能问答

13.2 四路混合检索

13.3 六层上下文处理

处理层规则
权限过滤未授权内容 100% 过滤；过滤在召回前，模型看不到。
版本过滤只保留当前有效版本；过期、作废、被替代版本排除。
去重合并不同来源的相同内容合并，节省 Token、避免干扰。
冲突标记不同文档说法不一致时，标记冲突，不随便选一个。
置信度排序权威 > 已确认 > 待审核；官方制度/SOP 优先。
长度控制最相关的排前面；控制预算；不塞无关内容。

13.4 引用与证据

逐句引用

  • 每个结论、步骤、数字都绑定来源：文档、页码、段落、表格区域。
  • 点击引用直达原文位置；原文不可见时提示原因。
  • 答案标注“依据版本 + 生效日期 + 最后验证时间”。
  • 高风险问题引用覆盖率 100%。

Evidence Pack

  • 保存问题、候选、权限快照、上下文、模型版本、Prompt 版本、回答、引用。
  • 按 request_id 可回放整条链路，用于排障与审计。
  • 证据包可导出给审计/质检，但受权限与密级约束。
  • 证据撤回后，相关答案自动降级并通知责任人。

13.5 拒答与不确定性

场景处理
无授权证据拒答；不提示具体缺失内容
证据不足拒答并建议补充知识/咨询专家
只有过期证据提示过期，不给当前结论
存在冲突证据展示冲突双方与来源，不强行下结论
问题要求越权信息拒答；不泄露存在性
要求无依据推测拒答；可给“需要哪些信息”的追问
高风险决策缺少官方来源只给参考证据，不给最终建议

13.7 官方答案与规则知识

官方答案

  • 高频、高风险问题配置经过审批的标准答案。
  • 包含条件、例外、适用范围、有效期、Owner、证据。
  • 草稿 → 评测 → 审批 → 灰度 → 发布 → 复审 → 替代/回滚。
  • 证据或版本失效时自动降级并通知责任人。

规则知识

  • 制度、流程、报价、质量、HR、财务等可判断适用条件的知识。
  • 尽量结构化：条件、要求、例外、生效期、责任部门。
  • 进入可测试规则引擎/Policy-as-Code，不只存在 Prompt 中。
  • 回答必须检查适用范围、时间与例外条件。

纠错

缺口

  • 所有调用生成审计记录与 Evidence Pack；高风险动作可人工中断。
14 · Quality Operations

14 · 知识质量运营

知识库不是一次建设完成，而是持续运营的产品。平台把“发现质量问题 → 变成任务 → 分派责任人 → 处理 → 验证”做成闭环， 并用健康度、资产盘点、贡献度等指标让治理可量化。

14.1 质量标签与断言状态

标签含义处理方式
EXTRACTED从源数据明确提取的事实可进入检索；仍需符合治理级别
INFERRED基于规则/模型推导的关系标记推导来源；Owner 确认后升级
AMBIGUOUS低置信度候选不进入正式检索；推送审核
未审核迁移或新入库但未走完审核可搜索但标注；不进入高风险回答
已验证最近一次复审确认有效展示“最后验证于”；正常参与回答

14.2 决策知识作为一等节点

制度规定、SOP 流程、会议决议、决策记录作为独立知识节点，与执行知识建立“规范、依据、影响”关系。员工看到一条执行要求，一键就能看到“为什么这么定、谁定的、什么时候定的”。

决策节点

决议、背景、依据、责任人、生效时间、替代关系。

执行节点

SOP、流程、检查表、培训材料、系统配置。

关系

规范、依据、影响、派生；支持“为什么”溯源。

14.3 用户反馈闭环

反馈处理阈值与升级
有用 / 没用低分进入质量任务；连续低分触发复审达到最小样本（如 ≥ 20 次）且差评率超阈值
“这条已过时”临时降权；推送 Owner 确认3 人以上或高风险领域立即处理
“答案不对”定位引用与段落；生成纠错任务影响官方答案时立即下线
补充建议进入候选；审核后合并—

14.4 知识缺口与冲突

缺口发现

  • 高频搜索无结果、低满意度问题、问答拒答聚类。
  • 图谱中“应有但缺失”的节点与关系（如某领域缺核心 SOP）。
  • 输出“缺口清单 + 推荐专家 + 建议模板”，分派补充。

冲突与重复

  • 冲突：不同权威来源结论不一致；展示双方，不强行合并。
  • 重复：相似知识检测；建议合并、保留主版本、建立映射。
  • 合并需审批；合并后保留来源与历史，链接不失效。

维度指标用途

应用配额、调用统计、异常告警、Key 轮换。

16.5 模型与 Prompt 管理

模型能力本身也需要被管理：路由、版本、评测、成本、防护。平台不把模型调用散落在各功能里，而是通过统一网关管理。

能力规则
模型路由按任务（解析/抽取/问答/审核预审）与密级路由；敏感内容只走允许的模型。
版本管理模型、Prompt、检索策略、规则统一版本化；灰度发布；可回滚。
评测上线前跑黄金问题集；对比准确率、引用覆盖、拒答、成本；不达标不发布。
成本Token 预算、缓存、限流、降级；按空间/场景分摊。
防护输入输出安全检查；Prompt 注入防护；敏感信息脱敏；日志不落原文。
降级模型不可用 → 备用模型 / 仅搜索；不泄露上下文；可观测告警。

可观测

17.3 安全要求

安全底线

  • 权限先行：检索前过滤；未授权内容不进入召回、重排、Prompt、引用。
  • 租户隔离：不同企业/法人数据隔离；跨租户共享需双方审批。
  • 加密：传输 TLS；存储加密；密钥托管 KMS；敏感字段脱敏。
  • Prompt 注入防护：文档内容不能覆盖系统规则；隐藏指令检测；指令/数据分离。
  • 模型边界：按密级路由模型；敏感内容不出域；不进入训练集。
  • 审计：登录、搜索、问答、下载、分享、权限、发布、Agent 调用全留痕；日志防篡改。
  • 接口安全：OAuth/OIDC、API Key 轮换、IP 白名单、签名、幂等、限流。

18.1 Walking Skeleton

P0 必须跑通的最小闭环

  1. 管理员创建空间，配置权限与审核流程。
  2. 作者上传一份 SOP，系统解析、提取元数据与实体。
  3. 作者校对并提交审核，系统生成审核基线与预审清单。
  4. 审核人查看差异与证据，审批通过，生成审批凭证。
  5. 知识发布并生效，进入搜索与问答索引。
  6. 另一位用户提问，系统返回带引用的答案与证据包。
  7. 用户点“有用/没用”，反馈进入质量任务。
  8. 权限撤销后，该用户在所有入口立即看不到内容。
